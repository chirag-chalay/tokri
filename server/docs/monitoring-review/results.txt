CONFIRMED ISSUES FIXED
- Critical and access/debug events previously shared a drop queue; failures existed
  only as in-memory counters. Added priority, explicit fallback/health and shutdown handling.
- Viewer reads shared the writer queue and could delay writes. Readers now run independently.
- Dates such as 2026-02-31 were accepted; status filtering ignored outcome when status existed.
- HTTP-200 failed payments were labeled success. Provider transport/business outcomes separated.
- Duplicate COD QR/cash handlers could both update a previously unpaid order.
  A synchronized read-interleaving probe exposed two update events (cod-race-before.jsonl).
  Conditional updates now produce one paid transition under concurrent QR/cash replays,
  while preserving the original returned order/customer/items shape.
- Deleted records incorrectly appeared in new values; now new:null, old=deleted record.
- Unknown numeric metadata and approved strings could leak sensitive values.
  Tightened the allowlist and string redaction; applied redaction to reader output too.
- Non-directory/permission errors could appear as empty logs; malformed rows were silently skipped.
  Explicit storage/corruption alerts added; debug controls remain available when reads fail.
- Filter labels did not have stable accessible names; explicit labels/IDs added.
- Native fatal stderr could include secret-bearing messages/stacks; safe fail-stop logging added.
- CLI --input-type=module was incorrectly inherited by file workers; filtered from worker arguments.
- Legacy feature test assumed free Express delivery and incorrect cancellation arithmetic.
  Updated tests to current Morning-only offer, Express minimum/fee and valid-order counts.
  Business delivery/tax rules preserved.
