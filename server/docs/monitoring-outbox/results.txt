WHAT CHANGED
The former file-only critical path is now a MySQL transactional outbox for payment
and admin audit events. MonitoringOutbox contains only sanitized JSON. A separate
MonitoringOutboxBudget row bounds retained logical bytes under concurrent producers.
No broker, external service, new dependency or live database change was introduced.

Critical ORM mutations and their audit/payment records commit in one InnoDB
transaction. Rollback removes both. Callback and array transactions preserve the
backend's ordering/result semantics. Ordinary scalar unique-key admin snapshots
use locked reads, including concurrent price changes. Deletion has old values and
new:null. Composite-key snapshot reads remain best effort.

Provider attempts/results and webhook outcomes explicitly await outbox persistence.
Auxiliary request-completion summaries enqueue asynchronously; actual database
transitions have their own atomic records. Accounts/access/debug/errors retain the
existing bounded asynchronous file path. Debug-control audit persistence completes
before the control response.

A background relay claims pending events with a 60-second lease, plans/persists a
daily target date, writes/syncs the private file and directory, then acknowledges
in MySQL. Stable IDs deduplicate repeated persistence and file replays. Bounded
negative indexes accelerate exact file-ID checks; collisions never discard data.
A truncated final JSON line is repaired before replay. Recovered old events retain
the original timestamp and get a recoveredAt marker in a current daily file.

Pending events are never removed by age or capacity cleanup. Delivered rows expire
(default seven days) or are reclaimed first to make room. Retry delay is bounded
at five minutes. A crash can leave an active lease; it is reclaimed automatically
after expiry. Shutdown finishes current delivery and producer persistence, leaving
the rest of the backlog durable rather than waiting for unbounded file I/O.

FAIL-OPEN BOUNDARY
File failures, queue pressure and process termination do not lose successfully
persisted outbox events. If the outbox/database/schema/producer limit/byte budget
itself cannot accept a NEW event, checkout is preserved and a sanitized emergency
record plus health/capacity failure is emitted. That new event is NOT claimed as
durable. Existing pending events remain intact. This is finite durable recovery,
not an unlimited archive or a guarantee when all storage is unavailable.
The dashboard warns on unavailability, retries, enqueue failures and high usage.
